## **🎯 Complete Step-by-Step Guide**

### **Step 1: Create GitHub Repository (2 minutes)**

1. **Go to GitHub.com** and sign in
2. **Click "+" icon** → **"New repository"**
3. **Name it:** `yourusername.github.io` (replace with your actual username)
4. **Make it Public** (required for free GitHub Pages)
5. **Don't check** any of the initialization options
6. **Click "Create repository"**

**Why this naming:** GitHub Pages automatically recognizes `username.github.io` repositories and hosts them at that exact URL.

### **Step 2: Configure Jekyll & LaTeX Support (3 minutes)**

#### **2.1: Create `_config.yml`**

1. **Click "Create new file"** in your empty repo
2. **Name it:** `_config.yml`
3. **Paste this content:**
```yaml
plugins:
  - jekyll-relative-links
relative_links:
  enabled: true
  collections: true

title: "Your Blog Name"
description: "Your blog description"
url: "https://yourusername.github.io"

markdown: kramdown
kramdown:
  math_engine: null
```

4. **Replace** the title, description, and URL with your details
5. **Commit the file**

**Why this works:**

- `jekyll-relative-links` makes markdown links work between files
- `math_engine: null` disables kramdown's math processing, letting MathJax handle it
- This allows standard LaTeX syntax instead of kramdown's weird `$$ inline $$` format

#### **2.2: Create LaTeX Support**

1. **Create file:** `_includes/head-custom.html`
2. **Paste this content:**
```html
<link rel="icon" type="image/x-icon" href="/assets/favicon.ico">

<script>
window.MathJax = {
  tex: {
	inlineMath: [['$', '$'], ['\\(', '\\)']],
	displayMath: [['$$', '$$'], ['\\[', '\\]']],
	processEscapes: true,
	processEnvironments: true
  },
  options: {
	ignoreHtmlClass: "tex2jax_ignore",
	processHtmlClass: "tex2jax_process"
  }
};
</script>
<script type="text/javascript" id="MathJax-script" async src="https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-mml-chtml.js"></script>
```

3. **Commit the file**

**Why this works:**

- MathJax 3 with custom configuration to handle standard LaTeX delimiters
- `inlineMath: [['$', '$']]` enables normal `$formula$` syntax
- `displayMath: [['$$', '$$']]` enables normal `$$formula$$` blocks
- `math_engine: null` prevents kramdown from interfering

### **Step 3: Enable GitHub Pages (1 minute)**

1. **Go to repository Settings** → **Pages** (left sidebar)
2. **Under "Source":** Select **"Deploy from a branch"**
3. **Branch:** Choose **"main"**
4. **Folder:** Leave as **"/ (root)"**
5. **Click "Save"**

GitHub will show you the URL where your site will be published.

### **Step 5: Prepare Your Content Structure**

#### **5.1: Article Format**

**Each article should use this YAML front matter:**

```mardown
---
title: "Your Article Title"
date: 2024-05-31
article_number: 1
---

# Your Article Title

Your content goes here...

## Math Examples

Inline math: $E = mc^2$

Display math: (standard latex)
$$
\sum_{i=1}^{n} \frac{(x_i - \bar{x})^2}{N}
$$

## Images

![Description](/images/your-image.png)
```

**Why this structure:**

- `title`: Used for page titles, browser tabs, and listings
- `date`: For chronological reference (you can use any date format)
- `article_number`: Sequential numbering for perfect control over article order
- No categories/tags keeps it simple and prevents rendering issues

#### **5.2: Convert Your Obsidian Files**

**Filename changes:**

- `Physics Notes.md` → `physics-notes.md` (no spaces)
- Use consistent naming like `2022_05_21_article_1.md`

**Content changes:**

- Add YAML front matter to each file
- Convert `![[image.png]]` → `![Description](../images/image.png)`
- Keep your existing LaTeX math syntax - it will work now!

### **Step 6: Create Auto-Updating Homepage**

1. **Create file:** `index.md`
2. **Paste this content:**
```markdown
---
title: "Your Blog Name - Data Science & Analysis"
---

<link rel="stylesheet" href="/assets/style.css">

# 📊 Your Blog Name

Welcome to my blog! Here you'll find articles about data science, programming, and analysis.

## 📚 All Articles

<div class="article-list">
{% assign all_articles = site.pages | where_exp: "page", "page.path contains 'articles/'" | where_exp: "page", "page.title != nil" | sort: "article_number" | reverse %}
{% for article in all_articles %}
  <div class="article-item">
	<h3><a href="{{ article.url }}">{{ article.title }}</a></h3>
	<p class="article-meta">
	  📅 {{ article.date | date: "%B %d, %Y" }} | 
	  📄 Article #{{ article.article_number }}
	</p>
	<a href="{{ article.url }}" class="read-more">Read Article →</a>
  </div>
{% endfor %}
</div>

## 🧮 Math Examples

Standard LaTeX syntax works perfectly:

Inline: $E = mc^2$

Display:
$$
\int_0^\infty e^{-x^2} dx = \frac{\sqrt{\pi}}{2}
$$

Complex formulas:
$$
\sum_{i=1}^{n} \frac{(x_i - \bar{x})^2}{N-1}
$$

---

*Total articles: {{ all_articles.size }}*
```

3. **Replace "Your Blog Name" with your actual blog name**
4. **Commit the file**

**How this works:**

- `{% assign all_articles = site.pages...` gets all pages from the `articles/` folder
- `sort: "article_number" | reverse` sorts by your article numbers (highest first)
- The loop creates a styled article card for each post
- Liquid templating automatically updates when you add new articles

# Complete Guide to Portfolio Optimization

In this article, I'll explain modern portfolio theory and implement it in Python.

## Theory

The portfolio return can be calculated as: $r_{portfolio} = \sum w_i \cdot r_i$

The portfolio variance is more complex due to correlations:

$$
\sigma_{portfolio}^2 = w^T \Sigma w
$$

where $w$ is the weight vector and $\Sigma$ is the covariance matrix.

## Implementation

	:::python (or with encapsule the coding block with ```)
	import numpy as np
	import pandas as pd
	
	def calculate_portfolio_return(weights, returns):
		return np.sum(weights * returns)
```
